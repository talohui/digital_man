# 灵山胜境数字人 AI 导览 · 业务总览

## 1. 项目背景

灵山胜境是位于无锡的国家 5A 级佛教文化主题景区,核心景点包括 88 米灵山大佛、72000㎡ 灵山梵宫、九龙灌浴、五印坛城等,日均接待游客上万人。

景区现有数字化服务存在三类典型痛点:

1. **讲解供给不足**:专业讲解员价格高、覆盖有限,游客购买二维码自助讲解后听完即关,缺乏交互。
2. **路线靠经验拍**:景区内 30+ 景点,游客平均停留 4-6 小时,大部分人凭运气逛,**首次游客 60% 以上漏掉自己最感兴趣的内容**。
3. **管理拍脑袋**:园方对"哪类游客在哪个景点停留多久、对什么内容感兴趣"几乎没有量化数据,运营优化全靠经验。

本项目针对以上三点,做了一个**手机即开即用、不下载小程序**的"AI 数字人导游 + 个性化路线 + 管理看板"一体化系统,作为 软件杯 A5 赛道(景区数字化导览)的参赛作品。

## 2. 用户与角色

### C 端 - 游客
- 入口:扫码 / 微信分享链接 / 手机浏览器直接访问
- 设备:**手机优先**(覆盖 iOS Safari、Android Chrome、微信内置浏览器)
- 行为:看景点介绍、问数字人、看推荐路线、跟着地图走、给路线打分
- 不需要下载 App、不需要注册

### B 端 - 景区运营
- 入口:浏览器进 `/admin`(数据大屏) + DataEase(深度分析)
- 角色:运营 / 市场 / 内容运营 / 园方决策层
- 行为:看实时访问、看转化漏斗、看推荐效果、看满意度、按时段/年龄段/兴趣标签下钻

## 3. 核心场景

### 场景 A:首次来玩的散客
小王刚下高铁打开链接,选了"佛教文化 + 摄影"两个偏好标签 →
首页推荐"东方艺术殿堂深度路线",同时显示"为什么推荐这条"(匹配 87%、佛教 92% + 摄影 78%、平均停留 3.5h)→
进地图,**底部 sheet 默认收起**,地图全屏展示路线 →
点景点 marker,sheet 滑出显示"灵山大佛 · 第 1/8 站 · 下一站梵宫" → 点「讲解」进入景点详情,数字人开口讲解,音色亲切 → 全程能问数字人"这个手印什么意思""票价含哪些"等问题,毫秒级回复。

### 场景 B:再次重游的本地客
李姐第 3 次来,熟门熟路想跳过基础内容 → 在「我的」tab 看到自己的画像(佛教 0.8、亲子 0.4)和"已游历 12 站"→ 选择"专家路线",数字人直接讲深度内容(华藏世界琉璃工艺、敦煌艺术影响),不再啰嗦"灵山大佛多高"。

### 场景 C:景区运营周一晨会
小陈打开 B 端大屏 → 看到上周末佛诞节活动期间满意度从 0.72 升到 0.81、九龙灌浴漏斗转化率提升 14% → 下钻看具体哪条推荐路线带来这部分增长 → 决定本周推一个"佛诞主题路线"上首页。

## 4. 与传统二维码语音讲解的差异化

| 维度 | 传统二维码讲解 | 本项目 |
|---|---|---|
| 形态 | 单次录音 + 文字 | **数字人 Live2D 形象** + 实时 TTS,有视觉陪伴感 |
| 交互 | 单向播放 | 实时**双向问答**,游客随时打断追问 |
| 内容来源 | 人工脚本录制 | 灵山知识库 RAG,**事实严格 grounded**(实测 39/40 正确,97.5%) |
| 个性化 | 一份脚本所有人 | 按 6 维兴趣向量(佛教/历史/摄影/亲子/美食/养生)推送路线 |
| 地图 | 静态图 | 腾讯地图 +**腾讯步行规划真实路线** + 拖拽抽屉 |
| 离线 | 必须有网 | **PWA + Service Worker**,二次访问近 0 请求 |
| 数据回传 | 无 | 全埋点 → analytics-server → DataEase 大屏 |
| 安装 | 扫码后保留页面 | **可"添加到主屏",PWA 全屏 App 体验** |

## 5. 产品价值主张(一句话)

> 让每个游客都拥有一位**懂灵山、懂自己、随叫随到**的专属数字导游,让景区管理者第一次能用数据说话。

可拆成三句宣传语:

- **对游客**:不下载 App,扫一扫就有一位会答任何问题的 AI 导游。
- **对景区**:全链路埋点 + 满意度看板,每一条推荐路线的效果都可量化。
- **对评委**:实测数字人冷启 0.67s、问答 0.7-8s、首屏 32kB,移动端体验对标小程序。

## 6. 项目范围与边界(诚实声明)

**做了什么**:

- C 端移动 Web(React + PWA + 自写 SW)
- 数字人(Fay + Cubism Live2D + qwen-plus)
- 知识库 RAG(ChromaDB + bge-large-zh)
- 推荐(本地 6 维余弦匹配 + 可选 Gorse 离线召回)
- 后端事件流(Spring Boot + H2)
- B 端大屏(React /admin)+ DataEase 接入

**没做什么(明确声明,避免被评委追问)**:

- **没接入景区真实生产数据库** —— 演示用脱敏样本(522 条历史样本 + 12 条路线 + 30+ 景点)
- **没做票务支付** —— 票务页是 mockup,真实场景对接景区现有票务即可
- **没做安卓 / iOS 原生 App** —— 只做 Web,PWA 已覆盖"加到主屏"体验
- **数字人形象使用 Cubism 官方示例 Haru** —— 真实落地需委托美术做灵山主题形象(规划阶段已有方案,本次未落地)

## 7. 关键合作依赖

| 依赖 | 用途 | 备选 |
|---|---|---|
| **阿里云百炼 qwen-plus** | 数字人对话主模型 | 可换 GLM4 / DeepSeek(代码已抽象) |
| **百炼 text-embedding-v3** | 记忆系统向量化 | 可换本地 bge |
| **bge-large-zh-v1.5**(本地) | 知识库检索向量 | HF Hub 离线模式,已下载到本地 |
| **腾讯地图 JS API** | 地图底图 + 步行路线 | 可换高德,但路线规划格式不同需适配 |
| **Edge TTS**(免 key) | 数字人语音合成 | 已接入,稳定 |

## 8. 一段话摘要(可直接放在 PPT 第二页)

> 灵山胜境数字人 AI 导览是为软件杯 A5 赛道开发的一体化景区数字化系统。游客手机扫码即可获得 Live2D 数字人讲解、个性化路线推荐、实时知识问答和无下载的小程序式 PWA 体验,所有交互全埋点回传 Spring Boot 分析后端,接入 DataEase 形成 B 端管理大屏。数字人对话基于 Fay + 阿里百炼 qwen-plus,知识严格依据灵山自建知识库(RAG 准确率 97.5%),实测响应延迟 0.7–8 秒,首屏 JS gzip 32kB,二次访问近 0 网络请求,**满足真实景区高并发、弱网、零下载的部署需求**。
