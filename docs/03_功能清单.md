## F1 数字人形象与交互

### F1.1 Live2D 数字人渲染
- 模型:Cubism 4 官方示例 Haru(`demo/public/live2d/haru/*`,12MB 已本地化)
- 渲染:`demo/src/components/Live2DStage.tsx` + `demo/src/lib/live2dManager.ts`
- 多场景:每个场景(home / map / spot:xxx)独立 sessionId,数字人状态(`idle/thinking/speaking/listening`)按场景隔离

### F1.2 实时语音合成 + 嘴型同步
- TTS:Fay 调 Edge TTS,音频按句流出
- 前端:`demo/src/lib/audioLipsync.ts` 读取播放音频音量峰值 → 驱动 Live2D 嘴部参数
- 队列:`enqueueAudio` 串行播放避免覆盖

### F1.3 多输入通道
- 文字:`ChatPanel` textarea(自动撑高)
- 语音:`demo/src/lib/browserAsr.ts`(浏览器原生 SpeechRecognition) + `voiceAsr.ts`(可切云端 ASR)
- 按住麦克风、松手发送(全局 pointerup 监听,移出按钮也能松)

## F2 智能问答

### F2.1 RAG 知识库
- 知识源:灵山 30+ 景点 + 票价 + 常见问答 → 38 条 chunk(`lingshan-rag/data/chunks/lingshan_chunks.jsonl`)
- 向量化:bge-large-zh-v1.5(本地,HF 离线模式)
- 存储:ChromaDB(`lingshan-rag/chroma_db/`,集合 `lingshan_guide_v2`)
- MCP server:`lingshan-rag/mcp_server/server.py`,STDIO 协议供 Fay 子进程调用
- 实测准确率:**39/40 = 97.5%**(评测集 `lingshan-rag/data/eval_questions.jsonl`)

### F2.2 Grounding 强制约束(防幻觉)
- 关键改动:`lingshan-rag/scripts/rag_utils.py` 的 prestart 工具输出,把"事实必须逐字采用"约束**焊进工具返回内容**
- 软化版:`数字人开源项目/Fay-main/llm/nlp_cognitive_stream.py` 中加"事实之外可发挥语气/温度",兼顾准确与温度

### F2.3 流式 LLM(单调用快路径)
- 模型:阿里百炼 qwen-plus(非思考模型,流式 TTFT 低)
- planner 模式:输出 `{"action":"finish","message":"..."}`,**message 字段边生成边推送给 TTS 与前端**
- 单次 LLM 调用即完成(原方案需要 planner + final 两次调用)

### F2.4 记忆系统
- 短期:每轮对话进 memory_stream,Embedding 用 text-embedding-v3
- 反思:启动批次触发记忆反思,生成元认知节点
- 关键优化:`question()` 注入 planner 的记忆条数从 10 减到 **4 条**,提示词更紧凑

### F2.5 LLM 连接保活
- 后端:`数字人开源项目/Fay-main/llm/execution_manager.py` 启动 45s 心跳线程
- 前端:`demo/src/store/useChatStore.ts` WS 指数退避重连 + 离线发送队列

## F3 个性化导览

### F3.1 6 维兴趣向量
- 维度:佛教文化 / 历史人文 / 摄影出片 / 亲子家庭 / 美食养生 / 禅意养生
- 文件:`analytics-server/src/main/java/com/lingshan/analytics/service/PersonaEngine.java`
- 输入:游客点选标签 / 历史行为
- 输出:`UserProfile`(6 维向量)持久化到 H2

### F3.2 路线推荐 + 解释
- 文件:`analytics-server/.../service/RecommendExplainService.java`
- 算法:每条路线预定义 6 维特征 → 余弦相似度排序
- 解释:输出各维度贡献率 → 自然语言模板
- API:`GET /api/recommend/explain/{userId}`
- 前端展示:`demo/src/components/RouteCard.tsx` + `ProfileBadge.tsx`

### F3.3 个性化端到端
- 进入选择偏好 → 推荐路线 → 在景点回答时上下文带入偏好 → 反馈回流更新画像
- API:`GET /api/profile/{userId}`

## F5 满意度与反馈

### F5.1 显式信号
- 路线 5 星评分:`MobileMapPage.tsx` 自写星级组件(替代 antd Rate)
- 👍 / 👎 单题反馈:`MobileGuidePage.tsx` / `SpotGuidePage.tsx`
- API 端点:`POST /api/rate/route`、`POST /api/rate/spot`

### F5.2 隐式信号
- 路线完成率(到达多少站)
- 景点停留时长(进入 → 离开埋点)
- 中途离开率 / 追问次数 / 追问长度

### F5.3 汇总算法
- 文件:`analytics-server/.../service/AnalyticsService.java`
- 公式:`displayScore = 0.65 × 显式 + 0.35 × 隐式`,加贝叶斯平滑(避免单次反馈过度影响)
- API:`GET /api/satisfaction/summary` / `GET /api/satisfaction/trend`

## F7 PWA 与离线

### F7.1 Service Worker
- 文件:`demo/public/sw.js`(自写,~70 行)
- 策略:static cache-first / HTML network-first / 其余 stale-while-revalidate
- **二次访问近 0 网络请求**

### F7.2 PWA Manifest
- 文件:`demo/public/manifest.json` + `demo/public/icon.svg`
- 支持 iOS apple-touch-icon + 安卓 maskable
- 用户可"添加到主屏",启动屏一致绿色主题

### F7.3 启动性能优化
- 路由级 lazy:`SpotGuidePage`、`AdminDashboard`、`GuideMapPage` 全部按需加载
- Vite manualChunks:antd / Live2D / react / antd-icons 单独 chunk,长效缓存
- 移动游客首屏 vendor-antd 完全不下(只用在 lazy 路由)
- PostHog 空闲帧懒加载,首屏不下 180kB
- Live2D / ChatPanel 在 home 空闲帧预热
