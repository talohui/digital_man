# 小灵情绪、人设与语音交互修复设计

## 目标

修复游客表达强烈负面情绪时仍显示微笑的问题，统一数字人身份为“灵山小灵”，并确保手机端按住说话、松手识别后自动发送。

## 已确认交互

- 语音采用“按住说话、松手发送”，不启用持续监听或唤醒词。
- 正面与中性表达可以微笑；负面表达显示担忧/流泪神态。
- 负面回应播放语音时保留担忧神态，同时驱动实时说话口型。
- 数字人只能自称“灵山小灵”或“灵山胜境数字人导游”，不得自称 Fay、通用助手或暴露底层框架名称。

## 根因

1. 前端负面意图词表缺少“痛苦、绝望、崩溃、撑不住”等强负面表达，“我好痛苦”被当作中性输入，初始化为 `happy`。
2. `comfort` 状态虽已映射到 Live2D 的担忧/流泪表情，但音频播放期间没有接管嘴部开合，无法同时表现担忧和说话。
3. Fay 运行配置仍声明名字为 Fay、男性、助理、陪伴；系统提示虽追加了灵山导游语气，却没有覆盖身份字段，也未禁止暴露底层名称。
4. 手机端已有 MediaRecorder → Fay `/api/asr-transcribe` → 阿里云一句话识别 → `sendMessage` 链路，需要通过回归测试和真机等价页面验证其按住/全局松手/自动发送行为。

## 设计

### 情绪识别与表情

在现有 `fayEmotion` 规则中补充强负面词组，并保持“用户输入情绪优先于服务端通用 speaking 状态”的策略。`comfort` 状态继续使用现有 `f06` 担忧/流泪表情。音频播放时不把整个状态改成普通 `speaking`，而是允许 `comfort` 状态启用嘴部开合接管，使担忧表情与口型同时存在；播放结束后仍回到本轮负面情绪状态，直到本轮结束。

### 人设

在后端系统提示构建处加入项目级不可变身份约束，覆盖通用 Fay 配置：名字为“灵山小灵”，女性，职业为“灵山胜境数字人导游”。身份问题必须以该身份自然回答；“Fay”只能作为内部技术实现存在，不能出现在面向游客的自我介绍中。配置层同步修改非敏感人设字段，保证其他读取配置的链路也一致。

### 语音提问

保留现有云端优先策略：局域网手机访问使用 MediaRecorder 录制，松手后上传 Fay，由阿里云 ASR 返回文本，再复用文字 `sendMessage`。按钮外松手由全局 `pointerup`/`mouseup` 收口。录音不足、权限拒绝、服务不可达和识别为空继续给出明确提示；识别成功只发送一次。

## 测试与验收

- 单元测试：`我好痛苦`、`我快撑不住了`、`我很绝望` 均映射为 `comfort`；中性问题仍映射为 `happy`。
- 单元测试：`comfort` 音频播放允许口型接管，但视觉状态保持 `comfort`。
- 后端测试：构造系统提示时包含“灵山小灵”和禁止自称 Fay 的身份约束。
- 语音测试：按住开始、全局松手结束、识别成功自动调用一次发送，失败不发送。
- 在线验收：依次询问“我好痛苦”“你是谁”，再完成一次按住说话提问；观察担忧表情、说话口型、身份回答与自动发送。

## 非目标

- 不增加持续监听、唤醒词或后台常驻录音。
- 不重做 Live2D 模型或新增表情素材。
- 不改动 RAG 检索与答案准确率逻辑。
