# 天气问答上下文与主动提醒设计

## 目标

让“灵山小灵”在每轮导览问答中使用可信的实时天气上下文；当同一游客首次遇到雨雪雷、高温或大风高湿等风险天气时，主动播报一次对应的安全提醒，同时避免重复打扰。

## 范围

- 天气事实继续由 analytics-server 通过腾讯地图 WebService 获取，Key 仅保存在部署环境变量。
- Fay 服务端读取 analytics-server 的公开天气摘要并写入小灵的系统提示词。
- 安全提醒必须由规则生成；大模型只能用自然语言衔接导览建议，不能虚构天气、预警、医疗或救援指引。
- 本期不新增前端强制弹窗、不改变 RAG 索引、不启动第二份 RAG 服务。

## 数据流

```text
腾讯天气
  -> analytics-server /api/public/weather（缓存、路线策略、安全摘要）
  -> Fay WeatherContextProvider（2 分钟本地缓存）
  -> question() 系统上下文 + 首次风险提醒
  -> 小灵文字 / 语音回复
```

天气服务不可用、超时或未配置 Key 时，Fay 不注入天气内容，也不显示错误给游客；原有问答链路继续运行。

## 天气策略与安全文案

| 风险状态 | 触发条件 | 系统事实与路线策略 | 一次性主动提醒 |
| --- | --- | --- | --- |
| `wet-surface` | 天气描述含“雨”“雪”或“雷” | 优先室内停留路线 | “当前可能有降水，台阶和石板路较湿滑，行走时请放慢脚步并留意脚下。” |
| `heat` | 晴/少云/多云且温度 ≥ 28℃ | 优先树荫较多路线 | “现在天气较热，建议随身补水、避开长时间暴晒，优先选择树荫或室内休息点。” |
| `wind-discomfort` | 湿度 ≥ 85% 或风力 ≥ 6 级 | 优先轻松路线 | “当前体感可能不太舒适，建议放慢游览节奏，注意防风并适时休息。” |
| `normal` | 其余情况 | 按兴趣偏好推荐 | 不主动提醒 |

规则优先级：雨雪雷 > 晴热 > 高湿/大风 > 正常。医疗、走失、闭园和道路封闭仍只走既有应急事件规则与官方处置文案。

## 去重与播报时机

- 以 `username + weatherRiskKey` 作为一次性提醒键。
- 风险状态从 `normal` 切换到任一风险状态，或风险类别发生变化时，在该游客下一次回复的开头插入一段固定安全提醒。
- 同一风险状态后续对话不重复插入；服务进程重启后允许再次提醒。
- 不在无风险天气下主动播报；游客主动询问天气、路线或出行建议时，大模型可基于当前天气上下文正常回答。

## 组件边界

### analytics-server

- `ScenicWeatherDto` 增加 `weatherRiskKey` 与 `safetyNotice`。
- `WeatherRouteAdvisor` 是唯一的天气策略来源：同时产出路线策略、游客可见的简短建议与安全文案。
- `/api/public/weather` 仅返回天气摘要、策略和安全文案，不返回腾讯 Key、完整上游响应或内部异常。

### Fay

- 新建独立 `WeatherContextProvider`，只负责请求、短缓存、校验并格式化 analytics 返回的数据。
- 默认请求 `http://127.0.0.1:5002/api/public/weather`；允许通过 `LINGSHAN_ANALYTICS_BASE_URL` 覆盖；超时不超过 800ms。
- `question()` 只接收格式化后的上下文和“本轮是否应播报”的固定文案，不直接访问腾讯天气。
- 提示词明确要求：天气事实以当前上下文为准；没有上下文时不得声称掌握实时天气。

## 测试与验收

1. analytics 单元测试验证四类风险策略、DTO 不泄露 Key、未配置 Key 返回服务不可用。
2. Fay 单元测试验证：天气上下文格式化、2 分钟缓存、超时安全降级、同游客同风险只提醒一次、风险变化再次提醒。
3. 问答提示词测试验证：有天气时包含更新时间和安全边界；无天气时不包含虚构天气描述。
4. 现有 analytics 全量测试、Fay 相关测试和 demo 前端构建必须通过。

## 非目标

- 不将天气原始数据写入游客画像或行为日志。
- 不把天气提醒做成医疗/救援建议。
- 不为本期新增客户端定时推送或重复语音播报机制。
