## 目标

将 `origin/feature/lingshan-map-3d` 中已经完成的四项能力定点迁移到当前主项目工作区：新版地图端、C 端本地字体、首页客流跳转、GLB 地标运行时。迁移之外的 NBA、应急事件、游客隐私、RAG、Fay、B 端配置和现有 C 端业务必须保持不变。

来源分支为：

`origin/feature/lingshan-map-3d`

## 集成策略

采用子系统定点替换，不执行整分支 merge，也不批量 cherry-pick。新增的独立地图文件从来源分支迁入；主项目中已经修改过的共享文件必须手工合并，仅加入四项能力需要的 import、路由、入口和状态衔接。

共享文件包括但不限于：

- `demo/src/App.tsx`
- `demo/src/main.tsx`
- `demo/src/mobile/MobileHomePage.tsx`
- `demo/src/styles/global.css`
- `demo/package.json`

这些文件不得使用来源分支整文件覆盖。

## 范围一：新版地图端

迁移 `/map-3d-guide-c` 作为 C 端正式地图入口，并迁移以下子链路：

- `/map-3d-guide-c/poi/:poiId`
- `/map-3d-guide-c/route/:routeId`

地图子系统包含：

- 地图页面、POI 详情页和路线导览页；
- 地图状态机、图层管理、2D/3D 切换和相机恢复；
- POI 数据、景点媒体、路线数据和返回上下文；
- 浏览、路线和导航所需的移动端样式；
- 定位、方向、路线进度、偏航和模拟导航降级逻辑。

原 `/map`、旧景点入口和首页入口通过兼容跳转进入新版地图。主项目现有非地图路由保持原样。

## 范围二：C 端字体本地化

迁移 `demo/public/fonts/lingshan` 下的本地字体和 `demo/src/styles/c-app/cAppTypography.css`，并从 `demo/src/main.tsx` 引入。

字体只作用于以下 C 端表面：

- `.c-app-root`
- `.mobile-shell`
- `.splash-ad-page`
- `.immersive-guide`
- 标记为 C 端表面的数字人导览组件

标题使用 `LingshanSerif`，正文和操作控件使用 `LingshanSans`。管理后台不进入上述作用域，B 端继续保持现有字体和样式，便于后续独立改版。

## 范围三：首页客流跳转

保留主项目首页现有内容，仅替换和适配实时客流区域：

- “看地图”进入 `/map-3d-guide-c`；
- 点击景点客流条目进入对应 POI 详情；
- 保存首页滚动位置和返回锚点；
- 从地图或 POI 返回时恢复首页位置；
- 保留当前客流等级展示方式，不在本次迁移中新增后端实时接口。

本次迁移不把 B 端 `/admin/heatmap` 暴露给游客端。首页客流接入真实后端数据属于后续独立任务。

## 范围四：GLB 地标运行时

GLB 必须连同运行时成套迁移，不能只复制模型文件。迁移内容包括：

- 地标模型配置与人工校准参数；
- 近景/远景 LOD 选择；
- GLB 加载队列、并发控制、空间调度和内存回收；
- 地标显隐、卸载、场景切换和错误降级；
- 游客端实际引用的地标、园林和植被模型；
- Git LFS 跟踪规则和所需 LFS 对象。

主项目现有 `optimized-min` 轻量模型保留，不因替换而删除。约 1.1GB 的原始调试模型不进入游客端默认路径，也不作为本次迁移要求。Landmark Inspector 等校准工具仅保留开发用途，不出现在普通游客界面。

预加载保护保持来源分支行为：

- 桌面端预算 150MB，并发数 2；
- 移动端预算 36MB，并发数 1；
- 省流量模式、2G 和 slow-2g 网络跳过地标预加载；
- 地图详情页避免重复预加载无关地标；
- 模型加载失败时保留基础地图、POI 和路线功能。

## 明确不改动

- NBA、LLM 营销决策和决策执行闭环；
- 应急事件发布、提醒和路线约束；
- 游客隐私中心、授权、导出和删除；
- RAG 知识库及其服务进程；
- Fay、ASR、TTS、情绪识别和服务配置；
- analytics-server 既有业务；
- B 端页面结构与视觉样式；
- 用户密钥、记忆数据、数据库和当前未提交文件。

如果地图路由需要读取主项目新增加的应急路线约束，只允许增加适配层，不得删除或降级现有约束行为。

## 数据与错误处理

- 地图资源无法加载时显示可恢复的错误状态，不阻断其他 C 端页面；
- 腾讯地图脚本失败时保留重试或现有降级路径；
- GLB 失败只影响对应地标，不清空 POI 和路线；
- 返回上下文损坏时退化为正常进入首页或地图；
- 不在日志、URL 或前端状态中新增敏感配置。

## 验证标准

自动验证：

- 地图路由测试通过；
- 返回上下文与地图状态恢复测试通过；
- POI、路线、LOD 选择和 GLB 运行时测试通过；
- 现有首页、数字人、隐私和应急相关测试无回归；
- `npm run build` 成功。

浏览器验证：

- 首页“看地图”进入新版地图；
- 首页景点客流条目进入正确 POI；
- POI 返回首页恢复原滚动位置；
- 地图、POI、路线三条链路在手机视口可操作；
- 地标按距离加载和卸载，手机端不一次加载全部模型；
- GLB 请求失败后基础地图仍可操作；
- `/admin`、`/admin/decision`、`/admin/heatmap`、`/admin/kb`、`/admin/config` 路由仍然存在。

## 回滚原则

迁移前记录目标文件状态，并按四个子系统分批实施。共享文件只做小块补丁。任一批次验证失败时，仅回退该批迁移产生的改动，不重置工作区，也不恢复用户已有删除项或覆盖用户未提交文件。
