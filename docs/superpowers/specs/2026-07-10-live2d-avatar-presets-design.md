# Live2D 形象预设接入设计

## 目标

在不改变当前 C 端默认“小灵”形象、服装、音色或运行链路的前提下，接入三套新的本地 Live2D 形象，并让 B 端管理员能够预览和切换当前启用形象。

## 范围

- 保留当前默认形象作为默认预设，不修改现有数据库配置。
- 从 `digital_man.zip` 引入 `haru_final`、`haru_second`、`haru_third` 三个完整 Live2D Cubism 模型目录。
- B 端“数字人形象管理”展示四个固定预设的可选择卡片。
- 保存时复用现有 `live2dModelUrl` 与 `live2dPresetName` 字段；不新增数据库表和不开放任意 URL 输入。
- C 端继续从公开形象配置读取模型地址；刷新或重新进入页面后加载管理员保存的预设。

## 不在范围内

- 不替换默认小灵模型。
- 不改 Fay、RAG、TTS、音色同步和口型音频算法。
- 不提供上传任意 Live2D 包的功能。
- 不为新模型重新绘制服装贴图。

## 资源与预设

| 预设 | 模型地址 | 默认状态 |
| --- | --- | --- |
| 默认·小灵 | 保持现有模型地址 | 默认启用 |
| 小灵·雅致 | `/live2d/haru_final/haru_final.model3.json` | 可选 |
| 小灵·清新 | `/live2d/haru_second/haru_second.model3.json` | 可选 |
| 小灵·灵动 | `/live2d/haru_third/haru_third.model3.json` | 可选 |

三套新模型都包含 `ParamMouthOpenY`、`f00` 至 `f07` 表情和 `Idle` / `Tap` 动作组，因此沿用当前口型同步、正常、思考、微笑与安抚状态映射。

## B 端交互

“数字人形象管理”页将保留显示名、服装和音色配置，并新增“形象预设”卡片区：

1. 选中卡片后，右侧预览立即切换至对应模型。
2. 点击保存后，向已有 `/api/admin/avatar-config` 写入选中的本地模型 URL 和预设名。
3. 默认·小灵继续支持现有红色与绿色服装。
4. 选中新形象时，服装选择禁用并说明“该形象使用原始服装”；保存值回退为 `default`，避免不兼容贴图造成异常。
5. 音色选择及试听保持不变。

## C 端行为

游客端现有 `Live2DStage` 继续加载公开配置中的 `live2dModelUrl`。无需新路由或新接口；管理员保存后，游客刷新页面或重新进入数字人页面即可看到新形象。加载失败时保留现有错误兜底，不影响聊天面板与文字回答。

## 验证

1. 未执行保存时，C 端仍显示现有默认小灵。
2. B 端四张预设卡均可加载预览；切换不会遗留旧 PIXI canvas 或事件监听。
3. 保存任一新预设后，公开配置返回相应本地 URL 和预设名。
4. C 端刷新后加载该预设，仍能播放 Idle / Tap、切换表情，并以 `ParamMouthOpenY` 驱动口型。
5. 切回默认小灵后，原有服装切换仍正常。
6. 为预设解析和“非默认模型禁用服装”规则补充单元测试，并通过 TypeScript 检查与前端构建。
