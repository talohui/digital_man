# 大模型驱动的 Next Best Action 营销决策设计

## 1. 背景与目标

当前 B 端 `/admin/decision` 已展示 Next Best Action 决策卡片。`analytics-server` 会聚合近 24 小时游客提问、情绪、响应延迟、购票、消费、画像偏好，以及近 5 分钟景点访问热区，再由 `MarketingDecisionEngine` 通过固定规则生成推荐。

本次目标是让大模型成为主要决策生成器，同时保留现有规则引擎作为可靠兜底。大模型不可用、超时或输出不合格时，页面仍须返回可用建议，不能因为外部模型故障影响演示。

## 2. 已确认的产品决策

- 生成模式：大模型主生成，固定规则兜底。
- 接入位置：`analytics-server` 聚合数据后调用 Fay 内部接口；不在浏览器直接调用大模型。
- 模型配置：Fay 优先使用 `big_model_*`；未单独配置时回退 `gpt_*`。
- 触发方式：打开页面时自动生成，结果缓存 5 分钟。
- 手动刷新：管理员可点击“重新生成”跳过缓存。
- 输出数量：3～5 张决策卡片。
- 页面保留现有视觉风格，只补充生成状态、时间、刷新入口和窄屏适配。

## 3. 总体架构

```text
B 端决策页
  → GET /dashboard/marketing-decision
analytics-server
  → 聚合 DecisionInput
  → 调用 Fay /api/internal/marketing-decision
Fay
  → 读取大模型配置
  → 生成并解析结构化 JSON
analytics-server
  → 校验 DecisionResponse
  → 缓存 5 分钟
  → 失败时调用 MarketingDecisionEngine
B 端
  → 展示大模型结果或规则兜底结果
```

浏览器只与 `analytics-server` 通信。大模型 Key 保留在 Fay，不进入前端，也不复制到 analytics 配置中。

## 4. 输入数据

`analytics-server` 继续负责数据聚合，并向 Fay 发送结构化 `DecisionInput`：

- 近 24 小时提问总量与主要主题；
- 每个主题的出现次数、负面次数和最多 3 条脱敏样例；
- 正向情绪比例；
- P90 回答延迟；
- 近 5 分钟活跃会话数；
- 最热景点及其访问次数；
- 是否达到热区阈值；
- 主要游客画像和偏好标签；
- 最高消费品类及消费总额。

不向模型发送 API Key、管理员凭据、用户 ID、会话 ID或完整行为流水。问题样例在 analytics 侧限制长度和数量，避免把原始长文本直接传给模型。

## 5. Fay 内部决策接口

新增：

```http
POST /api/internal/marketing-decision
Content-Type: application/json
```

接口只监听 Fay 现有 HTTP 服务，由 analytics 通过内部地址调用。请求体包含 `DecisionInput`。响应体沿用现有 B 端所需结构：

```json
{
  "summary": "今日运营摘要",
  "cards": [
    {
      "title": "决策标题",
      "type": "营销机会",
      "priority": "高",
      "evidence": ["可核验的数据证据"],
      "reason": "决策原因",
      "actions": ["可执行动作"],
      "relatedTopics": ["主题"],
      "relatedSpots": ["景点"],
      "demoFallback": false
    }
  ],
  "actionTodos": ["按优先级汇总的行动"],
  "dataSources": ["真实输入来源"],
  "demoFallback": false
}
```

Fay 使用低随机性生成，并要求模型只输出 JSON。提示词明确禁止虚构人数、金额、比例、热区和事实；所有量化证据必须来自输入数据。

## 6. 输出校验与规则兜底

analytics 收到 Fay 结果后执行边界校验：

- `summary` 非空且长度受限；
- `cards` 数量为 3～5；
- `priority` 只能为“高”“中”“低”；
- 每张卡片必须有标题、类型、证据、原因和行动；
- 列表字段限制数量和单项长度；
- 不接受未知顶层结构或空卡片。

以下情况直接回退 `MarketingDecisionEngine.generate(input)`：

- Fay 不可达；
- 请求超过约 8 秒；
- Fay 未配置可用模型；
- 大模型返回非 JSON、字段缺失或空结果；
- 输出校验失败。

兜底响应附带生成来源和简短原因，但不向前端暴露内部异常栈、模型响应原文或密钥。

## 7. 缓存与刷新

- analytics 按单一运营看板缓存最近一次合格结果 5 分钟。
- 普通页面加载读取有效缓存，避免每次刷新都产生模型费用。
- 新增 `forceRefresh=true` 查询参数供“重新生成”按钮使用。
- 强制刷新仍受单进程互斥保护，避免管理员连点造成并发重复请求。
- 大模型失败产生的规则兜底结果可以短暂缓存，避免故障期间持续重试模型。

本次只实现进程内缓存，不引入 Redis 或数据库缓存。

## 8. 前端面板调整

在当前 `AdminMarketingDecisionPage` 上做定点调整：

- 标题区域显示结果来源：`大模型生成`、`规则兜底` 或 `演示样例`；
- 显示最近生成时间；
- 增加“重新生成”按钮；
- 加载结束后必须清除加载动画，即使请求失败；
- analytics 不可达时显示明确错误提示；
- 大模型失败但规则兜底成功时正常展示卡片，并以非阻塞提示说明已兜底；
- 修正窄窗口的顶部操作区、摘要卡片和内容网格横向溢出。

不改变现有深色视觉主题和主要信息层级。

## 9. 安全与日志

- Key 只由 Fay 读取，不进入 analytics 请求、响应或日志。
- 内部接口错误日志仅记录模型名、耗时、错误类别和请求追踪 ID。
- 不记录完整问题样例或模型原始输出。
- 前端只得到面向运营人员的简短兜底原因。
- 内部接口限制请求体大小，并只接受预期 JSON 字段。

## 10. 测试策略

### Fay

- 优先选择 `big_model_*`，缺失时回退 `gpt_*`；
- 正常结构化输出能够解析；
- Markdown 代码围栏中的 JSON 能安全提取；
- 非 JSON、缺字段和空卡片被拒绝；
- 日志和错误响应不泄露 Key。

### analytics-server

- 聚合后的 `DecisionInput` 正确发送给 Fay；
- 合格大模型结果成为最终响应；
- 超时、网络错误和非法结构回退规则引擎；
- 5 分钟内重复请求命中缓存；
- `forceRefresh=true` 绕过缓存；
- 并发刷新不会重复调用大模型；
- 响应标注正确生成来源与生成时间。

### 前端

- 展示三种生成来源状态；
- “重新生成”发出强制刷新请求；
- 成功、规则兜底、后端不可达三种状态均结束加载动画；
- 窄窗口不出现横向溢出。

## 11. 验收标准

- 有真实 analytics 数据且 Fay 模型可用时，页面显示 3～5 张由大模型生成、证据可追溯的决策卡片。
- 5 分钟内重复打开页面不重复调用模型。
- 点击“重新生成”会请求最新模型决策。
- 关闭模型或制造非法输出后，页面在可接受时间内展示规则兜底卡片。
- 大模型结果不会虚构输入中不存在的量化指标。
- B 端能明确辨识结果来源和生成时间。
- 现有规则引擎测试、analytics 测试、Fay 测试和前端测试全部通过。
