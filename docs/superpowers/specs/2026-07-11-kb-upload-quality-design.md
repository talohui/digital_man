# B 端知识库上传质量闭环设计

## 目标

管理员上传 PDF、Word、TXT 或 Markdown 后，系统不仅返回“写入了多少切片”，还要确认资料可解析、切片结构合理、重复版本被安全替换，并验证新资料能够被检索到。

## 方案

### 1. 解析与质量门槛

- Word 同时提取标题、正文和表格，表格按 Markdown 表格保留。
- PDF 按页提取并写入页码标题，保留来源边界。
- 清理空白、控制字符和重复段落；拒绝有效文本过少或无法形成有效切片的文档。
- 生成解析字符数、标题数、表格数、切片数、主题和景点等质量摘要。

### 2. 结构化切片

- 继续复用现有标题路径、景点和主题识别。
- 长文本优先在段落和句号边界切分；只有找不到边界时才按字符截断。
- 切片保留稳定的 `doc_id`、文档指纹、分类、页码/标题路径与上传时间。

### 3. 安全替换

- 对规范化后的正文计算 SHA-256 指纹。
- 相同内容重复上传返回 `unchanged`，不重复向量化。
- 同名文档内容变化时，先写入新切片并完成烟测，再删除旧版本；失败时删除新切片，保留旧版本。
- 为向量库增加按 `doc_id`/`doc_name` 查询和删除的窄接口。

### 4. 入库后烟测

- 从标题路径、景点、主题和首段生成最多 3 个确定性检索探针。
- 用当前向量检索查询探针，要求至少一个 Top5 命中新 `doc_id`。
- 上传响应返回烟测命中数、状态和示例探针。烟测失败视为入库失败并回滚。

### 5. B 端反馈

- 上传完成后展示状态：新增、替换或内容未变化。
- 展示解析字符数、标题数、表格数、切片数、识别主题和检索烟测结果。
- 明确区分“文件已接收”和“已验证可检索”，不再只用切片数代表成功。

## 错误处理

- 解析、质检、向量写入和烟测分别返回可理解的错误原因。
- 原始文件只在入库成功后保留；失败不留下半成品。
- 替换失败不删除原文档向量。

## 验证

- 单元测试覆盖 Word 表格、文本清理、句子边界切块、重复指纹和质量摘要。
- 服务测试覆盖首次上传、重复上传、替换、烟测失败回滚。
- 前端类型检查和构建验证上传结果展示。
