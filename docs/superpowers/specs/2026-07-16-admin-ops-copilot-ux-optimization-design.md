# 灵山 B 端与运营 Copilot 可用性优化设计

## 1. 背景与目标

当前 B 端已经具备总览、热力图、智能决策、应急协同、知识库、数字人、服务配置和运营报告等功能，但信息架构仍偏平铺，页面之间存在内容重复，部分状态只展示结果而缺少原因与恢复入口。运营 Copilot 已能读取全局上下文、生成只读分析，并起草应急或知识库变更，但连续对话、草案可读性、服务状态真实性和执行反馈仍不足。

本次优化采用渐进方案，不推翻现有 Spring Boot、Fay、RAG 和 React 架构，优先提升四条管理员主流程：识别态势、查看证据、形成行动、确认并追踪执行。

## 2. 范围

### 2.1 本次包含

- 重组 B 端导航与页面职责。
- 优化总览页和智能决策页的信息层级。
- 将全局 Copilot 升级为支持受控连续对话的运营工作区。
- 提供结构化回答、可读来源、草案预览、编辑、二次验证和分阶段执行反馈。
- 统一加载、空状态、错误、服务健康、数据新鲜度和操作结果反馈。
- 统一水墨灵山视觉下的产品组件、状态颜色、排版与动效。
- 保留现有接口兼容路径，避免破坏已有演示数据和未提交功能。

### 2.2 本次不包含

- 路网级实时路径规划。
- 游客端商品推荐模型的完整重写。
- 高风险心理事件的完整人工接管平台。
- 手机系统级推送服务。

这些能力需要独立数据和安全设计，不与 B 端可用性改造混在同一批次。

## 3. 信息架构

侧栏分为三组：

1. 运营监测：总览、客流热力。
2. 分析与处置：智能决策、应急协同、知识库、运营报告。
3. 系统管理：数字人、服务配置。

顶部栏统一显示当前层级、最后更新时间、真实服务健康状态、刷新入口和管理员身份。页面不再各自实现返回和状态区域。

页面职责如下：

- 总览：回答“现在发生了什么”和“今天先处理什么”。
- 智能决策：回答“为什么这样判断、建议怎么做、执行后发生了什么变化”。
- 热力图：呈现客流空间分布、趋势和异常区域。
- 应急协同：管理事件生命周期、影响范围和联动结果。
- 知识库：管理知识内容、来源、时效、质量和同步状态。
- 运营报告：管理报告生成、定时投递和历史审计。
- 数字人、服务配置：管理系统能力，不与日常运营工作混排。

## 4. 总览页设计

总览首屏由三层组成：

1. 实时运营态势带：客流、活跃应急、票务与消费、负面情绪风险、响应延迟、天气影响。
2. 今日优先事项：仅展示三至五项最高价值问题，包含严重程度、触发原因、更新时间和唯一主操作。
3. 趋势与观察：客流热区、票务消费、问答情绪、推荐效果和服务健康。

总览不重复呈现完整决策卡。点击异常、机会或待办后进入对应页面处理。模拟数字每秒更新时只过渡数字和趋势，不触发布局跳动。

## 5. 智能决策页设计

页面按“判断、证据、行动、结果”组织：

- 顶部展示运营摘要、生成时间、生成来源、缓存状态、数据范围和重新生成入口。
- 主体突出最高优先级决策，其余决策使用紧凑列表，支持类型、优先级和执行状态筛选。
- 每项决策依次说明问题、原因、证据、建议动作、执行状态和相关指标变化。
- 右侧展示本轮待办与执行进度；Copilot 使用全局抽屉，不在页面内部重复第二个输入框。
- 证据抽屉把内部英文字段和 JSON 转换为中文指标、结构化主题、时间窗口和可读样例。
- 历史版本展示新增、消失、优先级变化、数据来源变化以及大模型与规则兜底切换原因。

动作状态统一为 `待确认 → 已接受 → 执行中 → 已完成`，或进入 `已驳回`。状态更新成功后原按钮立即替换为当前状态，不继续显示“转为待办”。

## 6. Copilot 设计

### 6.1 全局入口与上下文

Copilot 作为全局悬浮入口存在于全部 B 端页面。抽屉打开后显示当前页面、当前查看对象、数据更新时间和真实服务状态。它可读取全局运营数据，但页面对象只作为额外上下文，不限制全局分析范围。

### 6.2 连续对话

前端为每次会话生成 `sessionId`，保存最近会话并在抽屉关闭后恢复。请求携带经过裁剪的近期对话历史；后端仅接受允许的角色和长度，重新构建最新运营上下文，再调用大模型。历史只辅助理解指代，实时数据始终以当前后端上下文为准。

### 6.3 结构化回答

分析回答包含：

- 核心结论。
- 关键证据。
- 建议动作。
- 风险或数据不足说明。
- 数据来源与更新时间。
- 大模型生成或规则兜底标识。

后端保留安全规则兜底，但兜底回答必须结合现有上下文生成可执行的只读建议，不能所有问题都返回同一句占位文本。

### 6.4 草案预览与编辑

应急草案预览事件类型、等级、标题、游客端正文、影响景点和路线、有效期、路线策略以及将触发的联动。知识草案预览变更类型、问题、答案、标签、来源和有效期。管理员可在确认前编辑允许字段，前端和后端均执行白名单校验。

### 6.5 确认与执行

写操作按以下阶段反馈：

1. 校验草案。
2. 重新验证管理员身份。
3. 写入目标服务。
4. 同步应急、路线、提醒或知识联动。
5. 返回业务编号与各子系统结果。

失败时保留草案，标记具体失败阶段并提供安全重试。确认接口继续防止重复提交，执行结果写入审计记录。

## 7. 服务健康与错误处理

顶部服务状态由聚合健康接口返回，至少区分 analytics、Fay、RAG、天气和大模型。状态包含 `正常、降级、未配置、离线、数据过期`，并附带最后检测时间。

页面错误提供明确原因和下一步动作：重新连接、前往配置、重试同步或查看简短诊断。大模型失败时显示规则兜底原因；应急发布成功但知识同步失败时不得把整次操作显示为完全成功。

## 8. 视觉与交互系统

采用克制的东方运营工作台：水墨背景降低对比度，内容使用带玉绿色倾向的实色表面，暖金用于文化识别和重点提示。楷体仅用于品牌与页面主标题，正文、按钮、表格和数字使用系统字体。

玉绿表示主操作和正常状态，琥珀表示警告，朱红表示危险操作和高风险事件；所有状态同时配合文字和图标。组件统一默认、悬停、焦点、按下、禁用、加载和错误状态。

抽屉、消息出现、数字更新和状态变化使用 150–250ms 的短动效；不动画化布局尺寸，并支持 `prefers-reduced-motion`。

## 9. 数据流

### 9.1 只读分析

管理员问题 → 前端附加 session 与受控近期历史 → analytics 聚合实时上下文 → Fay/LLM 生成结构化结果 → analytics 校验来源与结构 → 保存审计记录 → 前端展示结论、证据和动作。

### 9.2 写操作

Copilot 生成白名单草案 → 前端结构化预览与可选编辑 → 管理员重新验证 → analytics 原子领取草案 → 执行应急或知识动作 → 保存主结果与联动状态 → 前端显示分阶段结果及跳转入口。

## 10. 测试与验收

### 10.1 自动化测试

- 前端测试连续会话请求裁剪、结构化回答、草案编辑、确认防重复、状态恢复和错误映射。
- 后端测试会话历史白名单、上下文刷新、兜底回答差异化、草案字段校验、执行幂等和阶段结果。
- 现有智能决策、应急、知识库、天气与运营报告测试不得回归。

### 10.2 浏览器验收

1. 管理员在十秒内从总览识别最高优先级问题。
2. 从总览进入决策页，查看中文证据并接受一项建议。
3. 页面立即显示真实动作状态。
4. Copilot 连续追问三轮仍能理解指代并使用最新数据。
5. Copilot 草案可以预览、编辑、验证密码并执行。
6. 执行完成后可以跳转到目标页面查看业务对象。
7. 任一依赖服务停止时显示准确状态和恢复入口。
8. 规则兜底与大模型生成来源清晰可见。
9. 1440px、1024px 和窄屏布局无内容遮挡。
10. 构建、前后端测试及关键浏览器流程全部通过。

## 11. 实施顺序

1. 统一上下文、状态类型和测试夹具。
2. 改造 Copilot 连续对话与结构化结果。
3. 改造草案预览、编辑和执行反馈。
4. 重组全局导航、顶部状态和页面反馈。
5. 优化总览与智能决策页。
6. 统一其余 B 端页面的组件和错误状态。
7. 完成自动化测试、浏览器验收和性能检查。
