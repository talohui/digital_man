# 语音录音状态与空音频防护设计

## 问题

1. 云端 ASR 把“正在录音…”通过 `onInterim` 写入了聊天 `inputText`，因此在二次点击或回车等时序下，状态词可能被当成用户问题发送。
2. 录音上传只判断 `Blob` 分片数量，没有判断持续时间与有效大小。过快松手时可能得到只有容器头、没有音频帧的文件，百炼返回 `The audio is empty`。

## 修复方案

- `voiceDraft` 专门承载“正在录音…/正在云端识别…”及浏览器中间识别文本，`onInterim` 不再修改 `inputText`。
- `handleSend` 在录音中或存在语音处理状态时直接返回；输入框在录音中设为只读，按钮禁用逻辑保持为双重防护。
- 云端录音记录开始时间。少于 800ms 或合并后音频小于 1024 字节时不调用后端，统一提示“请按住至少 1 秒再松手”。
- 后端若仍收到供应商 `audio is empty` 错误，转换为简短中文错误，不将原始 HTTP 响应展示给游客。

## 验证

- RED 测试锁定：状态文本不进入 `inputText`；录音中不能发送；过短/过小音频不调用 `fetch`；后端翻译空音频错误。
- GREEN 后运行全部前端测试、后端 ASR 测试与生产构建。
- 重启 Fay，验证过短录音只显示本地友好提示，正常录音只发送识别结果一次。

## 范围

不改变“按住说话、松手发送”交互，不引入新依赖，不修改知识库或问答人设。
