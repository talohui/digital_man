# 答辩演示脚本

> 现场答辩用。提供 **2 分钟极简版**、**5 分钟标准版**、**8 分钟完整版** 三档。
> 顺序经过设计:**亮点优先 → 技术深度按需展开 → 数据收尾**。

---

## 演前 10 分钟必做清单(在路上反复念)

1. **电脑联网**(或开热点),浏览器打开 `http://localhost:5175`(或部署 URL),确认能加载
2. **手机连同一 WiFi**,扫码 `http://<电脑LAN_IP>:5175`,确认能进
3. **数字人对话试一句**「你好」,确认 Fay 在线 + 数字人会动
4. **DevTools 备好**:Chrome 打开开发者工具 Network 面板,准备演示首屏请求
5. **DataEase 大屏可选**:打开 `http://localhost:9080` 备用(评委问 B 端时切)
6. **PPT 准备 4 张备用截图**:数字人界面、地图 sheet 拖拽、推荐解释、大屏 —— 万一现场网络挂掉的兜底
7. **备用方案**:U 盘里准备录屏 60s 视频,网全断时直接放

## 2 分钟极简版(限时 + 评委催)

**第 0-15s · 一句话定位**
> 这是为软件杯 A5 赛道做的灵山胜境数字人 AI 导览,**手机扫码即用、不下载小程序**,游客对着数字人问任何问题都能秒回,后台同步回传管理大屏。

**第 15-60s · 三个 30 秒亮点**
1. **数字人对话**:[当场打字]「灵山大佛多高?」→ 数字人 1 秒内开口,语气自然,数字准确
2. **个性化路线**:返回首页 → 点选「佛教 + 摄影」→ 推荐 RouteCard 出现,带"为什么推荐"解释
3. **移动地图**:进地图 tab → 抓住底部 sheet 上拉 → 三档跟手切换 + 地图全屏 + 浮动状态绿圆点

**第 60-90s · 工程亮点**
> 首屏 JS gzip 32 kB(从 789 kB 降 96%),二次访问通过 Service Worker 近 0 网络请求,WebSocket 自动重连 + 离线发送队列,移动 4G 下稳定可用。

**第 90-120s · 数据闭环**
[打开 /admin 大屏] → 刚才的提问已经在事件流里 → 满意度、推荐转化、热门景点都实时更新。

## 5 分钟标准版(推荐主用)

### 开场(30s)
> 项目名灵山胜境数字人 AI 导览,软件杯 A5 赛道。痛点很简单:**景区讲解员贵、二维码语音听一遍就关、运营拍脑袋**。我们用数字人 + RAG 知识库 + 个性化推荐 + 数据看板四件套对应三个痛点。

### 演示 1 - 数字人问答(60s)
[手机扫码进站]
- "你好,我刚到灵山,先看什么?" → 数字人主动推荐
- "灵山大佛多高?" → **答 88 米 + 形象类比**(差不多 30 层楼那么高)
- "梵宫主要看什么?" → 答出星空穹顶 28m、华藏世界琉璃 + 小贴士

讲解点:
> 数字人基于阿里百炼 qwen-plus,知识严格依据自建灵山 RAG 知识库,**实测 40 题准确率 97.5%**,数字、年代、专有名词不编造。

### 演示 2 - 个性化推荐 + 解释(60s)
- 返回首页 → 点「佛教文化」+「摄影出片」
- RouteCard 出现:"东方艺术殿堂深度路线 · 匹配 87%"
- 点击 ProfileBadge → 弹出 6 维兴趣雷达 + "为什么推荐"模板

讲解点:
> 6 维兴趣向量与每条路线的预定义特征做余弦匹配,**每条推荐都有人类可读的解释,不是黑盒**。后端 Spring Boot,API 可单独调试。

### 演示 3 - 移动地图体验(60s)
- 进地图 tab → 全屏地图 + 浮动顶栏 + 状态绿圆点
- **抓住底部 sheet 上拉** → 三档切换,跟手流畅
- 点景点 marker → sheet 显示「第 2/12 站 · 灵山大照壁 · 下一站胜境广场」+ 「讲解」按钮
- 点「讲解」→ 进入景点详情,数字人开口

讲解点:
> sheet 拖拽用自定义 hook,touchmove 期间**绕过 React 直接改 DOM**,低端 Android 也能 60fps。三档对应不同信息密度,默认极简不挡地图。

### 演示 4 - 管理大屏(45s)
- Cmd+T 新开 tab 进 `/admin` → 实时事件流 + 满意度 + 推荐转化 + 热门景点
- (可选)切 DataEase 大屏 → 按时段/年龄段/兴趣标签下钻

讲解点:
> 满意度算法 = 0.65 × 显式信号 + 0.35 × 隐式信号 + 贝叶斯平滑。后端 Spring Boot + H2,可直连 DataEase 出深度看板。

### 收尾(15s)
> 总结一句:**手机扫码就有 AI 导游,运营第一次有数据看板**。技术细节、性能指标、代码地图全在 GitHub 仓库 docs 目录,谢谢评委。

## 8 分钟完整版(给充裕时间或评委追问深度时)

在 5 分钟版基础上,**每个演示后插入 30s 技术深度**:

### 数字人问答后插入:RAG 准确性原理(45s)
- 拉出 DevTools 看实际链路:前端 → Fay HTTP → planner LLM 流式调用
- 解释 grounding 强制约束:RAG 返回的资料里包含"事实必须逐字采用"指令,焊进工具输出,**无论后续 prompt 路径怎么走该约束都随上下文存在**
- 解释流式单调用:不是 planner + final 两次 LLM,而是单次 `{"action":"finish","message":"..."}` 边生成边推
- 展示性能埋点:`/tmp/lat_timing.log`

### 个性化后插入:推荐算法可解释(30s)
- 打开 `RecommendExplainService.java` 关键 30 行
- 解释余弦相似度 + 维度贡献率拆分
- 强调:**不是黑盒矩阵分解,是显式可调参**

### 地图后插入:移动工程难点(45s)
- 打开 `useBottomSheetDrag.ts`
- 解释为什么 touchmove 不走 React(避免 60Hz 重渲)
- 解释三档吸附:速度 > 0.55 px/ms 跨档,否则就近吸附
- 演示焦点管理:键盘 ESC 关浮层 + Tab 限制在浮层内

### 大屏后插入:数据闭环(60s)
- 拉出统一事件流端点 `POST /api/events`
- 演示前端任意操作 → 实时打到后端 → 大屏看板更新
- 强调:**前端 + 后端双埋点**,即使 PostHog 挂了本地通道仍工作

### 工程化收尾(30s)
- 打开 `SETUP.md` 翻 §9 FAQ → "我们写了 7 条常见问题排查"
- 打开 `docs/04_性能与指标.md` → "所有性能数字都能复现,测量脚本在仓库"

## 现场可能被问到的硬核问题 + 标准答案

### Q: "你们用了 qwen-plus,准确率高是不是因为模型本身好,跟你们关系不大?"
A: "不完全是。我们做的关键工作是 **grounding 约束**——把'事实必须逐字采用'指令焊进 RAG 返回内容,这样不管 prompt 路径怎么走都有这条约束。**模型只是引擎,流程设计才是关键**。同一模型 + 自由发挥的话,'施无畏印'会被答成'说法印'(我们 debug 时实测过)。"

### Q: "你们的延迟数据是不是优化前对比,实际跟竞品比怎么样?"
A: "竞品大多是单向语音讲解,没有交互能力,没有可比对象。横向对比的话,我们 0.7-2 秒首字延迟接近商用智能客服(类似京东京小智、淘宝阿里小蜜)水平,**这套链路全是开源 + 自研,可完整复现**。"

### Q: "移动端 sheet 拖拽手势库为什么不直接用 react-spring / framer-motion?"
A: "两个原因:第一,我们想把首屏 JS gzip 压到 32kB,引入 react-spring 直接多 20kB+;第二,我们的 hook 60 行,可读、可改、可测,**适合教学和后续维护**。生产环境上规模后可以再换。"

### Q: "PWA 加到主屏跟原生 App 比有什么区别?"
A: "三个权衡:1)PWA 无法用厂商深度 API(如 NFC、蓝牙),景区导览不需要;2)PWA 启动后基本能做到原生体感(全屏 + 主题色 + 离线);3)**PWA 无审核、即发即用,景区临时活动可以小时级上线**。原生 App 一两周走苹果审核,完全不匹配景区运营节奏。"

### Q: "数字人形象为什么用 Cubism 官方示例 Haru,是不是应付?"
A: "诚实回答:我们规划了一个灵山主题的小僧人形象,但是 Cubism 美术建模需要 3-4 周,**项目周期不足**,所以用 Haru 占位。**整套技术栈(Live2D 渲染、嘴型同步、TTS 调度)可以无缝换皮**,这是工程能力,不是临时拼凑。"

### Q: "数据库用 H2 是不是太简陋?"
A: "演示场景 H2 文件库零运维、500ms 启动,适合评委复现。**生产环境我们建议换 PostgreSQL**,JPA 抽象层一行配置切换。" 然后打开 `application.properties` 给评委看。

### Q: "WebSocket 断了怎么办?"
A: 当场 DevTools → Network → Throttle → Offline → 演示前端显示"正在重连..." → 切回 Online → 自动重连成功 → 此前打的字自动重发出去。
