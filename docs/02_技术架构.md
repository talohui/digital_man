## 2. 五层架构

| 层 | 组件 | 职责 |
|---|---|---|
| **接入层** | PWA Web + Service Worker | 移动优先 UI、底部 Tab、PWA 离线、SW 预缓存 |
| **数字人层** | Fay + Live2D + Edge TTS | 形象呈现、语音合成、嘴型同步、多场景上下文隔离 |
| **AI 推理层** | qwen-plus + bge-large-zh | 对话生成、知识检索、记忆向量化 |
| **业务后端** | Spring Boot + H2 | 行为分析、推荐、个性化、满意度 |
| **数据可视化** | /admin 大屏 + DataEase | 实时看板、运营分析、决策支持 |

## 3. 关键数据流

### 3.1 一次游客提问的完整链路

```
游客打字 "灵山大佛多高"
  │
  ▼
前端 ChatPanel → sendTextToFay (POST :5000/api/send)
  │
  ▼
Fay nlp_cognitive_stream.question()
  ├─ 1. 记忆检索 (text-embedding-v3, ~1s)  ← persistent Session
  ├─ 2. 预启动 RAG (MCP :5010, 本地 bge 检索, ~0.1s)
  │     └─ 返回 top-3 灵山讲解词 + grounding 约束指令
  ├─ 3. 构建 planner prompt (含记忆 4 条 + RAG context + 角色设定)
  ├─ 4. 调 qwen-plus 流式 (planner 模式)
  │     └─ 单次调用即输出 {"action":"finish","message":"嗯,灵山大佛..."}
  │        message 字段边生成边推给 TTS 边写入前端 WS
  └─ 5. 写记忆库 (异步,不阻塞返回)
  │
  ▼
前端 useChatStore.handleFayMessage
  ├─ 文本气泡(剥 <prestart>/<think>/_<isfirst> 标记)
  ├─ 同一轮多句合并到一个 assistant 气泡
  ├─ 音频 enqueue → 串行播放
  └─ 数字人 robotState 切换 (thinking → speaking → idle)
  │
  ▼
埋点 captureUserMessage / captureAiReply
  └─ POST :5002/api/events (analytics-server)
```

### 3.2 个性化推荐链路

```
游客选偏好标签 → useGuideStore.toggleTag
  │
  ▼
capturePreferenceUpdate (埋点 + 触发后端)
  │
  ▼
analytics-server PersonaEngine
  ├─ 把偏好标签映射到 6 维兴趣向量 [佛教/历史/摄影/亲子/美食/养生]
  ├─ 每条路线预定义 6 维特征向量
  └─ 余弦相似度排序 → 返回 top-N
  │
  ▼
RecommendExplainService
  ├─ 计算各维度贡献率 (e.g. 佛教 92% + 摄影 78%)
  └─ 生成"为什么推荐"自然语言文案
  │
  ▼
前端 RouteCard 渲染推荐 + 推荐解释 chip
```

### 3.3 满意度计算

```
显式信号(0.65 权)
  ├─ Rate 路线 5 星
  └─ 👍 / 👎 单题反馈

隐式信号(0.35 权)
  ├─ 完成路线百分比
  ├─ 在景点停留时长
  ├─ 主动追问数 / 长度
  └─ 中途离开率

  │
  ▼
analytics-server AnalyticsService.computeSatisfaction()
  ├─ 贝叶斯平滑(避免单次反馈过度影响)
  └─ 输出 [0, 1] 浮点值
  │
  ▼
GET :5002/api/satisfaction/summary
GET :5002/api/satisfaction/trend
```

## 4. 技术栈完整表

### 4.1 前端

| 类别 | 选型 | 版本 | 选型理由 |
|---|---|---|---|
| 框架 | React | 18 | 团队熟、生态广 |
| 构建 | Vite | 5 | 启动快、HMR 顺,生产 manualChunks 细粒度可控 |
| 路由 | react-router | 6 | 路由级 lazy 配合代码分割 |
| 状态 | zustand | 4 | 比 redux 轻,**无 provider 嵌套**,跨页面 store 友好 |
| 数字人 | Cubism 4 + pixi-live2d-display | latest | Cubism 是官方 SDK,pixi 渲染高效 |
| 地图 | 腾讯地图 JS API | 1.exp | 步行规划接口质量高 |
| PWA | 自写 Service Worker(no plugin) | - | 避免 vite-plugin-pwa 引入额外构建复杂度 |
| 埋点 | PostHog(idle 懒加载) | 1.x | SaaS 行为分析,可选 |
| 离线 | 自写 SW + IndexedDB SW Cache | - | 二次访问近 0 网络 |

### 4.2 数字人 / AI

| 类别 | 选型 | 备注 |
|---|---|---|
| 数字人框架 | Fay(Python) | 开源,流式 LLM/TTS/ASR 协同 |
| 主对话模型 | 阿里百炼 qwen-plus | 非思考模型,流式 TTFT 低 |
| Embedding(记忆) | 百炼 text-embedding-v3 | 跨语言、与 LLM 同账号 |
| Embedding(RAG) | bge-large-zh-v1.5 | 本地推理,HF 离线模式 |
| 向量库 | ChromaDB | 嵌入式,文件持久化 |
| TTS | Edge TTS | 微软免费,中文音色丰富 |
| LangChain | langchain_openai.ChatOpenAI | 兼容多家 OpenAI 协议 LLM |

### 4.3 后端

| 类别 | 选型 | 备注 |
|---|---|---|
| 框架 | Spring Boot 3 | 工业标准,DataEase 现成接入 |
| ORM | Spring Data JPA | 简化 CRUD |
| 数据库 | H2(文件库) | 零运维,演示部署快;生产建议换 PostgreSQL |
| 推荐 | 本地 6 维余弦(默认) + Gorse(可选) | 演示用本地,生产可上 Gorse |
| 可视化 | DataEase 2.x | 国产 BI,中文支持好 |

## 5. 部署形态

### 5.1 当前演示部署
```
开发机(macOS)
├─ Fay        (python main.py start)        :5000 / :10003
├─ RAG MCP    (Fay 自动子进程拉起)           :5010
├─ analytics  (mvn spring-boot:run)         :5002
├─ Frontend   (vite dev)                    :5173 / :5175
├─ Gorse      (docker-compose, 可选)        :8087
└─ DataEase   (docker-compose, 可选)        :9080
```

### 5.2 生产部署建议
- **前端**:`vite build` → 静态部署到 Nginx / 腾讯云 COS / CDN
- **Fay**:Docker 化 + systemd 守护进程
- **analytics-server**:打 jar,systemd 守护;数据库换 PostgreSQL
- **DataEase**:独立 docker-compose,挂景区运营 BI
- 全部走景区现有 SSL + WAF + 反向代理

## 6. 与传统架构对比

| 决策 | 传统做法 | 本项目做法 | 收益 |
|---|---|---|---|
| 数字人模型 | 全云端推理 | **Fay 本地编排 + 云端 LLM** | 延迟可控,记忆系统不外泄 |
| 知识库 | 全文检索 | **RAG + grounding 强制约束** | 准确率 97.5%,无幻觉 |
| 推荐 | 黑盒矩阵分解 | **6 维显式兴趣向量 + 自然语言解释** | 可解释、可调参 |
| 前端 | SSR / Next.js | **纯 SPA + PWA** | 部署简单,离线友好 |
| 埋点 | 仅前端 | **前端 + 后端双埋点** | 数据不丢、可审计 |
