# 灵山胜境核心游线 3D 空间表达规划

## 1. 规划目标

本项目不做完整景区数字孪生，也不做全景区精确三维重建。当前目标是做“核心游线驱动的艺术化 3D 导览地图”。

3D 地图应基于真实游览路线与真实空间关系，但采用低模、符号化、艺术化表达。它负责主视觉、景点探索、路线理解和沉浸式导览；腾讯地图仍作为真实 POI、经纬度、路线规划、真实导航和兜底能力。

推荐产品边界：

- `/scenic-3d-map`：核心游线艺术化 3D 地图，作为主视觉导览入口。
- `/map`：腾讯地图真实导览页，负责真实 POI、真实路线、定位和导航兜底。
- `/three-preview`：3D 资产测试页，用于查看低模占位和后续 `.glb` 模型。

本规划用于指导后续 `scenePosition` 调整、低模场景布局、Blender/3D 重建资产制作，而不是直接替代真实地图导航。

## 4. 真实空间关系表达原则

`scenePosition` 是艺术化 3D 坐标，不是经纬度。但 `scenePosition` 应尽量保持真实相对方向和路线顺序，不允许为了好看随意颠倒核心景点关系。

数据职责：

- `displayLocation`：用于真实地图展示点。
- `navLocation`：用于真实导航终点。
- `scenePosition`：用于 3D 场景展示。
- `poiId`：连接真实地图、3D 坐标、模型资产、讲解内容和路线站点。

真实到 3D 的映射原则：

| 真实地图要素 | 3D 表达方式 | 精确程度要求 | 备注 |
|---|---|---|---|
| 山体 | 低饱和青灰/墨绿远景山体、边缘剪影 | 中等，方向和背景关系合理即可 | 不挡核心建筑，不抢主视觉 |
| 太湖/水系 | 大色块、半透明淡蓝灰水面、留白边界 | 中等，整体方向和空间感要合理 | 不要求精确岸线 |
| 主路 | 金线/墨线主游线、少量控制点形成自然弧度 | 中高，路线顺序必须可信 | 不还原所有小路 |
| 广场 | 浅色地台、圆盘、平台、节点光环 | 中等，承接建筑和停留点 | 形状可艺术化 |
| 核心建筑 | 低模/符号化建筑体块或 `.glb` 模型 | 高，核心识别度必须强 | 先重轮廓、比例和位置关系 |
| 入口/出口 | 门楼符号、标牌、箭头、起终点节点 | 中等，动线功能清楚即可 | 真实导航仍交给 `/map` |
| 路线金线 | 三维曲线、节点圆环、分段高亮 | 中高，必须连接正确 POI | 不是精确步行导航 |

## 5. 山体、水系、道路、广场的表达规范

### 山体

- 山体作为背景意象，不作为可游览主体。
- 应位于真实方位相近的一侧，优先放在场景边缘和远景层。
- 不应遮挡灵山大佛、九龙灌浴、梵宫、五印坛城和主路线。
- 用低饱和青灰、墨绿、半透明材质表达。
- 山体高度应低于核心视觉锚点，避免压迫画面。

### 太湖/水系

- 太湖/水系用大色块表达，形成开阔山水意象。
- 位置应参考真实地图水域方向，建议作为场景一侧的留白和开阔面。
- 不要求精确边界，但要符合整体空间感。
- 水面颜色建议使用淡蓝灰、青灰，透明度较高，不做强反光。

### 道路

- 主游线用金线/墨线表达。
- 主线优先表达路线顺序、导览节奏和核心节点，不要求完整还原所有小路。
- 路线可以在相邻 POI 之间加入控制点，让路径更像可步行游线。
- 后续如接入园区路网，应保留“艺术路线”和“真实步行路线”的 UI 区分。

### 广场

- 广场用浅色地台、圆盘、平台表达。
- 广场用于承接核心建筑、游客停留点和讲解节点。
- 广场形状可以艺术化，但位置关系应合理。
- 佛前广场、梵宫广场、胜境广场应优先进入空间布局，因为它们能解释景点之间的停留和转场关系。

## 9. 风险与边界

- 不做完整景区数字孪生。
- 不做全景区精确三维重建。
- 不让 3D 地图承担未经校验的真实导航判断。
- 不把腾讯地图截图作为贴图。
- 不把重建得到的高面数模型直接放进前端。
- 不把宗教建筑/佛像做娱乐化夸张表达。
- 不用 3D 艺术路线冒充真实可走路线。
- 不在 POI 绑定未完成前做精确到点导航。
- 不牺牲 `/map` 的真实导航兜底能力。

## 10. 结论

3D 地图应围绕核心游线做精细表达，而不是扩大成完整景区数字孪生。

山、水、路、广场、建筑都要符合真实空间关系，但表达方式可以低模、符号化、艺术化。当前阶段先用低模和场景布局建立空间秩序，后续逐步替换核心建筑 `.glb` 模型。

这条路线比完整景区数字孪生更适合当前 demo：范围可控、视觉表达更集中、性能风险更低，也能保持腾讯地图作为真实导航底座的可靠性。
