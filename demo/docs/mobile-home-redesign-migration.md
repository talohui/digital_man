# C 端导览首页视觉迁移说明

> `PlaqueTitle`、`MountainGate` 及后续 C 端独立视觉组件的接口和使用边界，统一记录在 `docs/c-app-visual-components.md`。

## 迁移范围

正式移动端导览首页 `/` 使用水彩长卷背景、牌匾标题、山门内容容器、金色引导线和依次开门动画。桌面端 `/` 仍由原有 `HomePage` 渲染，本次不调整 B 端页面、地图核心逻辑或后端接口。

## 通用组件

- `src/components/mobile/home/PlaqueTitle.tsx`
  - `title`：牌匾标题内容。
  - `size`：`small | medium | large`。
  - `level`：标题语义层级 `2 | 3`。
  - 统一深绿色底、暖金边框和两侧挂耳。
- `src/components/mobile/home/MountainGate.tsx`
  - 接收任意 `children`。
  - `variant`：`route | services | crowd`。
  - 统一屋檐、立柱、米白渐变底板边界和门扇动画。
  - `delay` 控制页面入场时的开门顺序。
- `src/components/mobile/navigation/CAppBottomNav.tsx`
  - 正式 C 端五项主导航，由首页、消费、画像、规划等 `MobileShell` 页面统一复用。
  - 自身固定居中且最大宽度为 `430px`，不依赖父页面是否采用移动端容器。
  - “小灵”入口使用深绿圆形底座、暖金描边和米白外环持续强调，选中时增强金色光环。
  - 地图状态恢复、小灵返回上下文等正式跳转逻辑在组件内部统一维护。

## 入场动画

动画顺序必须保留：

1. 金色引导线用约 `4800ms` 沿整张背景画布从上向下持续点亮。
2. 引导线抵达游览路线锚点时，山门在约 `580ms` 开始开启。
3. 引导线抵达景区服务锚点时，山门在约 `1445ms` 开始开启。
4. 引导线抵达实时客流锚点时，山门在约 `2215ms` 开始开启。

门扇动画由 `MountainGate` 内部实现，正式首页门扇在对应时间点立即开始打开，不再额外保持关闭状态。系统启用 `prefers-reduced-motion: reduce` 时，跳过长动画并直接展示已开启状态。小灵气泡不再自动弹出，避免遮挡实时客流。

上述时间根据原引导线 `top: 21%`、`height: 69%` 的路径长度采样，并通过分段关键帧调整绘制速度：路线到服务段放慢、服务到客流段加快，使两次开门间隔接近。调整背景锚点、路径或分段速度后，需要同步重新计算开门时间，不能仅按模块纵向百分比估算。

## 背景坐标系

正式首页通过 `home-formal-artboard` 按原始背景图 `860 × 2385` 的比例建立统一画布。背景以画布内绝对定位的 `<img>` 等比显示，不使用 `cover` 裁切；游览路线、景区服务和实时客流分别锚定在画布高度约 `25.75%`、`37.65%`、`52.9%` 的位置。

后续调整模块与背景景物的对应关系时，应修改画布百分比锚点，不要重新使用按设备区分的固定 `top`、`bottom` 或连续 `margin-top`。375px、390px、430px 宽度均由同一坐标系等比例换算。

背景画布之后只保留约 `77px + safe-area-inset-bottom` 的滚动留白，与正式底部导航高度一致。页面滚动到底时，这段留白应落在固定导航下方；不要恢复旧版约 `142px` 的双倍底部间距。

## 普通 C 端页面容器

由 `MobileShell` 承载的首页、规划、购票、消费、画像等普通 C 端页面统一使用 `width: min(100%, 430px)` 的居中容器。设备宽度不超过 `430px` 时容器铺满屏幕，不增加边框和外边距；宽度超过 `430px` 时页面保持 `430px` 居中，剩余区域显示外围背景，并增加轻量左右描边与阴影。

统一底部导航、悬浮小灵和普通页小灵会话面板均以相同的 `430px` 边界居中。地图浏览、POI 详情、路线模拟导航和全屏小灵会话属于沉浸式页面，不强制套入普通页面容器。

## 暂不迁移的旧首页内容

以下旧功能在新设计中没有直接位置，本次按产品确认暂不迁移：

- Shell 顶部“当前路线”快捷按钮：`/map-3d-guide-c/route/:routeId`。
- 旧首页底部的当前路线名称与路线描述状态卡。

相关地图路线页和路由本身没有删除，只是不再从新版首页直接展示快捷入口。

## 数据说明

“实时客流”当前使用前端静态拥挤度配置和浏览器当前时间，不是真实实时接口。正式页面必须保留“演示数据”标识；后续接入实时接口时，可替换数据来源而不改变 `MountainGate` 和列表排版。
