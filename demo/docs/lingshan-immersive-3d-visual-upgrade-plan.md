# 灵山胜境沉浸式 3D 地图视觉风格升级方案

## 1. 当前定位

当前系统适合形成“双层地图 + 资产测试”的结构：

### 3D 艺术地图层

- 页面：`/scenic-3d-map`
- 作用：作为用户主视觉导览入口，承担景点探索、路线讲述、沉浸式体验。
- 当前定位：面向游客的艺术化 3D 景区地图，不追求真实 GIS 级精度。

### 真实地图导航层

- 页面：`/map`
- 作用：承担腾讯地图真实底图、经纬度 POI、真实路线、导航兜底。
- 当前定位：负责真实 POI、路线规划、景点聚焦、腾讯地图 walking route、InfoWindow 和后续真实导航能力。

### 资产测试层

- 页面：`/three-preview`
- 作用：测试低模占位和后续 Blender `.glb` 模型。
- 当前定位：开发测试页，不建议暴露为普通游客入口。

结论：3D 地图可以逐步替代腾讯地图的“视觉入口”，但不应完全替代腾讯地图的真实导航能力。更合理的产品形态是：用户先进入 `/scenic-3d-map` 感知景区和路线，再通过 POI 或路线按钮进入 `/map` 获取真实地图和导航兜底。

## 2. 当前 /scenic-3d-map 能力盘点

基于当前文件：

- `src/pages/Scenic3DMapPage.tsx`
- `src/components/scenic3d/Scenic3DMapScene.tsx`
- `src/data/lingshanMapData.ts`
- `src/data/scenic3d/lingshanAssetMap.ts`

当前已有能力如下。

### 3D 场景元素

`Scenic3DMapScene` 已经使用 React Three Fiber 渲染全屏 Canvas，包含：

- 地形底盘：圆形低模地面。
- 太湖/水面意象：两个浅蓝绿色椭圆水面区域。
- 远景山体：多个 coneGeometry 低模山体。
- 雾效：Three.js fog。
- 光照：ambientLight、hemisphereLight、directionalLight。
- 4 个核心低模地标：灵山大佛、九龙灌浴、梵宫、五印坛城。
- 3D 路线曲线：两层金色 Line，形成导览路径。
- 景点标签：使用 drei `Html` 标签显示中文景点名。
- OrbitControls：支持用户旋转、缩放、平移视角。

### POI scenePosition 数据化

`lingshanMapData.ts` 已为 4 个核心 POI 补充 `scenePosition`：

- `giant_buddha`
- `jiulong_guanyu`
- `fan_gong`
- `wuyin_tancheng`

`scenePosition` 是艺术化 3D 场景坐标，不是经纬度，也不用于真实导航。`Scenic3DMapScene` 通过 `lingshanPois` 读取这些坐标摆放地标，并保留 fallback 位置。

### 3D 路线数据化

`lingshanMapData.ts` 已定义：

```ts
export type LingshanSceneRoute = {
  id: string
  name: string
  description: string
  poiSequence: string[]
}
```

当前路线：

```ts
classic_3d_scene -> ['jiulong_guanyu', 'giant_buddha', 'fan_gong', 'wuyin_tancheng']
```

`Scenic3DMapScene` 接收 `routePoiSequence`，通过 `poiId -> lingshanPois.scenePosition` 生成 3D 金色路线曲线。

### 景点选择与高亮

`Scenic3DMapPage` 维护 `selectedPoiId`。左侧路线站点列表点击后更新选中点，3D 场景中对应模型会放大高亮，标签样式也随之变化。

### 3D 页面跳转真实地图

`Scenic3DMapPage` 已提供：

- `查看该景点真实地图`：跳转 `/map?poi=<selectedPoiId>`
- `查看整条路线真实地图`：跳转 `/map?sceneRoute=<currentRoute.id>`
- `返回真实地图`：跳转 `/map`

### /map?poi=xxx 和 /map?sceneRoute=xxx 闭环

`GuideMapPage` 已支持：

- `/map?poi=xxx`：自动选中并聚焦真实景点，使用景点级 zoom。
- `/map?sceneRoute=classic_3d_scene`：映射到真实 guideRoute `historical_culture`。
- `poi` 与 `sceneRoute` 同时存在时，`poi` 优先。
- query poi 初始聚焦后，用户手动点击其它站点，InfoWindow 可同步切换，不再被 query poi 拉回。

## 3. 与参考风格的差距分析

参考目标包括：

- Chartogne-Taillet：手绘/低多边形庄园地图、地块探索、hover 高亮、纸张质感、故事化地图。
- 水墨杭州：水墨感、雾气、城市/山水意象、镜头推进、东方审美。

当前差距如下。

### 场景构图

当前地形仍是简单圆形底盘，核心点位分布偏原型验证。缺少更清晰的景区主轴、入口、广场、水系、山体边界、路线层级和空间故事线。Chartogne-Taillet 的优势是地块关系清晰，水墨杭州的优势是山水城市结构有层次；当前还需要把灵山胜境的“入园轴线、九龙灌浴、大佛轴线、梵宫和坛城片区”组织成可读的场景构图。

### 模型资产

当前地标全部是 placeholder 几何体。它们能表达“这里有一个地标”，但还不能表达灵山大佛、九龙灌浴、梵宫、五印坛城的形象差异和文化识别度。缺少 Blender 导出的核心 `.glb` 模型、地形底盘模型、道路/广场/牌坊/台阶等环境资产。

### 材质风格

当前材质是简单 `meshStandardMaterial`，偏普通低模。还缺少：

- 纸张肌理或宣纸底色。
- 水墨晕染边缘。
- 建筑体块的克制金色、石色、木色。
- 水面的柔和反射或透明层次。
- 路线金线的卷轴/丝线质感。

### 光照与雾效

当前已有雾、半球光和方向光，但还比较功能化。需要进一步形成东方山水氛围：

- 前景清晰、远景渐隐。
- 山体和水面被雾气分层。
- 核心景点有柔和主光。
- 不做强烈游戏感高对比灯光。

### 标签与 UI

当前标签是普通 HTML 按钮样式。还缺少手绘地图式标签、卷轴式信息卡、路线章节点、hover 反馈和更统一的视觉层级。左侧和右下浮层功能完整，但还没有完全融入“艺术地图”的风格。

### 路线表达

当前路线是金色 3D 曲线，已经具备方向感，但仍是简单曲线。还缺少：

- 分段路线。
- 当前站/下一站状态。
- 路线流动高亮。
- 卷轴式路线叙事。
- 真实路线与艺术路线的区别提示。

### 交互反馈

当前支持列表选择、模型点击、高亮和 OrbitControls。还缺少 hover 高亮、点击后的镜头飞行、路线分段播放、景点故事卡片展开、返回真实地图的更清晰导航路径。

### 镜头语言

当前是固定初始相机 + OrbitControls。还没有形成“进入景区、推进到地标、沿路线游览”的镜头语言。后续可以加入：

- 默认俯视斜角地图视角。
- 点击景点镜头飞行。
- 路线播放镜头。
- 返回全景视角按钮。

### 文化氛围

当前已具备“山水 + 金线 + 佛教核心地标”的雏形，但宗教文化表达仍偏弱。需要通过庄重色彩、建筑秩序、留白、雾气、轴线、标签文案、景点故事卡共同建立灵山胜境的文化氛围。

### 与真实导航的连接

当前已经通过 `/map?poi=xxx` 和 `/map?sceneRoute=xxx` 连接真实地图，基础闭环已打通。后续差距在于：

- 3D 页面尚未显示真实导航状态。
- 尚未显示用户大致位置。
- 尚未将真实经纬度映射到 3D 场景坐标。
- 尚未接入园区自定义路网和路线进度。

## 4. 视觉目标定义

灵山胜境 3D 地图建议采用以下视觉关键词：

- 水墨留白
- 佛教文化庄重感
- 太湖山水意象
- 低多边形符号化
- 金线导览路线
- 柔和雾效
- 手绘标签
- 卷轴式路线
- 东方园林/佛教建筑秩序感
- 克制、轻量、可读

明确不要做：

- 不做写实完整数字孪生。
- 不做过度娱乐化佛教形象。
- 不做高面数复杂模型堆叠。
- 不把腾讯地图截图当贴图。
- 不让 3D 场景承担未经校验的真实导航判断。
- 不把 Live2D 数字人改造成 3D 数字人。
- 不为了视觉效果牺牲移动端可用性。

## 5. 3D 地图替代腾讯地图视觉层的可行性分析

### 结论

3D 地图可以替代腾讯原始地图样式中的“用户主视觉导览入口”，但不应替代“真实地理坐标与导航兜底能力”。

未来可以让首页和底部导航中的“地图”优先进入 `/scenic-3d-map`。`/map` 保留为“真实地图模式”或“导航详情模式”，用于真实定位、真实 POI、真实路线、路线兜底和后续导航。

### 方案 A：保守方案

`/scenic-3d-map` 是独立沉浸式入口，`/map` 是真实地图页。

优点：

- 风险最低。
- 不影响已验证的腾讯地图导览能力。
- 适合继续打磨 3D 视觉和交互。
- 用户需要真实导航时可以明确跳转 `/map`。

风险：

- 两个地图入口并存，用户可能需要理解二者区别。
- 3D 地图的主入口地位不够强。

适合阶段：

- 当前阶段到视觉升级前中期。
- 适合继续验证 3D 场景风格、性能、交互。

### 方案 B：推荐方案

用户默认进入 `/scenic-3d-map`，真实导航按钮再跳 `/map`。

优点：

- 3D 地图成为主视觉和主导览入口。
- 产品观感明显区别于普通腾讯地图。
- 真实导航仍由 `/map` 兜底，可靠性不丢失。
- 符合“酒庄地图/水墨杭州”式沉浸式体验方向。

风险：

- 需要在 UI 中反复说明“艺术化导览”和“真实地图导航”的区别。
- 需要保证移动端 WebGL 性能。
- 需要让真实地图入口足够清晰，避免用户找不到导航功能。

适合阶段：

- 完成阶段 A 代码级视觉升级后。
- 至少需要 3D 页面视觉达到“可展示”的水准，并通过移动端性能验证。

### 方案 C：激进方案

完全用 3D 地图替代 `/map` 的视觉层，只在后台调用腾讯地图服务。

优点：

- 用户只看到统一的 3D 地图体验。
- 产品辨识度最强。
- 后续可以形成完整沉浸式导览系统。

风险：

- 工程复杂度高。
- 需要自建经纬度到 3D 坐标映射。
- 需要处理用户定位、偏航、路线进度、弱网、地图服务失败等问题。
- 如果 3D 路线和真实可走路线不一致，会造成用户误解。
- 对移动端性能和 WebGL 稳定性要求高。

适合阶段：

- 不适合当前阶段。
- 只有在真实 POI、园区路网、3D 坐标映射、资产性能和导航兜底都成熟后再考虑。

## 6. 导航功能如何接入 3D 地图

导航应分成真实导航数据和 3D 展示数据。

### 真实导航数据

- `lingshanPois.displayLocation`
- `lingshanPois.navLocation`
- 腾讯地图 POI
- 腾讯 walking route
- 后续园区自定义路网
- 后续用户定位数据

真实导航数据负责回答：

- 景点真实在哪里。
- 导航终点应该落在哪里。
- 用户现在在哪里。
- 真实步行路线怎么走。
- 偏航后如何恢复。

### 3D 展示数据

- `lingshanPois.scenePosition`
- `lingshanSceneRoutes.poiSequence`
- `lingshanAssetMap`
- 3D 路线曲线
- 后续模型 transform、LOD、thumbnail

3D 展示数据负责回答：

- 艺术化地图中景点摆在哪里。
- 哪些景点构成 3D 导览路线。
- 每个 POI 对应哪个模型或 placeholder。
- 视觉路线如何表达。

### 通过 poiId 连接

`poiId` 是连接真实地图、3D 场景和讲解内容的关键主键。一个 `poiId` 同时连接：

- 真实地图坐标
- 3D 场景位置
- 3D 模型资产
- 讲解内容
- 路线站点
- 真实地图跳转

当前已经形成基础闭环：

- `lingshanPois.id`
- `lingshanPois.displayLocation`
- `lingshanPois.navLocation`
- `lingshanPois.scenePosition`
- `lingshanAssetMap.poiId`
- `lingshanSceneRoutes.poiSequence`
- `/map?poi=xxx`

### 可实现的导航层级

1. 3D 中展示推荐路线。
2. 3D 中点击景点跳转真实地图。
3. 3D 中显示当前路线和下一站。
4. 3D 中显示用户大致位置。
5. 3D 中根据园区路网展示路线进度。
6. 真实转向导航仍由腾讯地图或自有路网兜底。

建议顺序是先完成 1-3，再进入 4-6。不要在真实边界、真实 POI 和可走路网未校验前，把 3D 路线包装成精确导航。

## 7. 分阶段视觉升级路线

### 阶段 A：代码级视觉升级

不依赖 Blender，只改 Three.js 场景：

- 优化颜色体系：从普通低模色改为水墨灰绿、宣纸白、克制金线、佛教建筑暖金。
- 优化雾效：增加远景层次，让山体、水面和地标有前后关系。
- 优化水面：用更柔和的半透明水域或多层水面表达太湖意象。
- 优化山体：减少普通锥体感，改为更平缓的山脊线和远景剪影。
- 优化路线曲线：金线加外发光或流动段，区分当前路线和已走/未走。
- 优化标签样式：从普通按钮改为手绘地图标签或小卷轴标签。
- 优化景点高亮：增加底座光环、标签强调、路线节点强调。
- 优化镜头初始角度：更像地图浏览，而不是通用 3D demo。
- 增加 hover/click 动效：hover 提示、点击轻量镜头推进。

### 阶段 B：低模场景构图升级

- 根据灵山真实空间关系重排 `scenePosition`。
- 增加南门入口区。
- 增加主轴线、广场、道路、水系。
- 增加山水边界。
- 增加出口区。
- 增加路线层级：主线、支线、回到真实地图入口。
- 增加景区边界轮廓，但明确它是艺术化边界，不等于真实法定边界。

### 阶段 C：Blender 核心资产替换

- `lingshan_buddha.glb`
- `jiulong_guanyu.glb`
- `fan_gong.glb`
- `wuyin_tancheng.glb`
- `terrain_base.glb`
- 缩略图和 LOD

要求：

- 先替换 4 个 core_3d。
- 每个模型保持低多边形、轻量化、符号化。
- 宗教类形象保持庄重，不做夸张娱乐化表现。
- 模型体积和 draw call 必须可控。

### 阶段 D：沉浸式交互升级

- 点击景点镜头飞行。
- hover 高亮。
- 景点故事卡片。
- 路线分段播放。
- 当前站/下一站进度。
- 返回真实地图按钮更明确。
- 真实地图入口分成“查看景点真实地图”和“查看整条路线真实地图”。

### 阶段 E：导航能力增强

- 用户定位。
- 将真实经纬度映射到 3D `scenePosition`。
- 园区路网。
- 路线进度。
- 偏航提示。
- 真实地图兜底。
- 离线/弱网策略。

阶段 E 前置条件较多，必须在 POI、navLocation、边界、路网和性能验证后推进。

## 8. 第一批代码改造建议

建议阶段二十七先做 `/scenic-3d-map` 视觉风格轻量升级。

范围建议：

- 不改导航逻辑。
- 不改 `/map`。
- 不引入真实 `.glb`。
- 不修改 POI 坐标。
- 优化颜色、雾效、水面、标签、路线高亮、按钮与布局。

建议修改文件：

- `src/components/scenic3d/Scenic3DMapScene.tsx`
- `src/pages/Scenic3DMapPage.tsx`
- `docs/map-3d-development-log.md`

可执行改造项：

- 调整 Canvas 背景和雾色为更柔和的水墨灰绿。
- 将地形底盘从单圆盘升级为多层岛形或圆角轮廓组合。
- 水面增加透明材质、边界柔化和颜色层次。
- 山体从锥体改为低矮山脊组合。
- 路线金线增加节点圆点和当前站强调。
- 标签改成更轻的卷轴/手绘地图样式。
- 左侧路线卡和右下景点卡统一成更克制的宣纸半透明风格。
- 保留真实地图跳转按钮，并强化“真实导航以腾讯地图为准”的提示。

## 9. 风险与注意事项

- 3D 主视觉不能牺牲真实导航可靠性。
- 移动端性能风险：Three.js、drei、Html 标签和模型加载都可能影响低端机。
- WebGL context lost 风险：需要保留降级提示或真实地图入口。
- 模型体积风险：核心模型必须控制体积、贴图和材质数量。
- 宗教景观表达风险：佛教文化景观应克制、庄重、符号化。
- 腾讯地图 API Key 安全风险：不能在文档、提交或截图中泄露 Key。
- 路线展示与真实可走路线不一致风险：3D 路线必须标注为艺术化导览路线。
- 用户误以为 3D 路线就是精确导航的风险：UI 中必须明确“艺术化导览”和“真实地图导航”的区别。
- 经纬度到 3D 坐标映射风险：没有真实路网前，不应做精确导航判断。
- 资产版权风险：不要使用未经授权的贴图、地图截图或模型素材。

## 10. 结论

3D 地图可以作为灵山胜境项目的主导览视觉，承担第一印象、景点探索、路线叙事和沉浸体验。

腾讯地图仍应作为真实导航底座，承担真实 POI、经纬度、walking route、InfoWindow、真实地图兜底和后续定位导航。

当前最合理的产品形态是：

```text
3D 艺术地图主入口 + 腾讯地图真实导航兜底
```

下一步不应直接投入复杂 Blender 模型，而应先进行 `/scenic-3d-map` 的代码级视觉升级。原因是当前场景已经具备数据闭环和页面入口，先把颜色、雾效、水面、路线、标签、布局和交互反馈做到接近目标风格，可以更快验证“酒庄地图/水墨杭州”方向是否成立，再决定 Blender 资产制作优先级。
