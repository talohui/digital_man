# 灵山胜境 Blender MCP 与 AI 3D 建模路线方案

## 1. 目标

当前目标不是完整景区数字孪生，而是围绕核心游线制作可在 Web 端稳定加载的 3D 资产包。资产需要服务：

- `/three-preview`：单个模型加载、比例、朝向和材质验证。
- `/scenic-3d-map`：沉浸式 3D 导览地图中的核心地标表达。
- 后续 Android 原生增强方案：可能复用 GLB / glTF 模型资产。

第一批核心模型建议为：

- 灵山大佛
- 梵宫
- 九龙灌浴
- 五印坛城

这些模型应以低模、庄重、符号化、移动端可加载为原则，不追求完整景区数字孪生和写实级复杂重建。

## 2. 三种建模路线对比

| 路线 | 适合内容 | 优点 | 风险 | 当前建议 |
| --- | --- | --- | --- | --- |
| Codex + Blender MCP | 低模符号化建筑、规则几何体、场景批处理、材质统一、缩放居中、设置原点、批量导出 GLB | 可自动化重复操作，适合生成规则资产和整理场景，能减少手工机械步骤 | 不能保证复杂佛像和建筑细节审美；执行 Blender Python 需要本地安全边界；仍需人工验收 | 适合做低模草模、导出自动化和资产清理辅助 |
| AI 3D 生成 / 重建工具 | 从单图、多图或视频快速生成复杂初版 mesh，获得大体轮廓和纹理参考 | 速度快，适合探索形体和复杂外观，能作为首版参考模型 | 结构可能不准，贴图脏，面数高，法线、比例、原点和拓扑混乱；宗教建筑或佛像可能失真 | 可作为粗模来源，但不能直接作为最终前端资产 |
| 手工 Blender 低模建模 / 清理 | 核心地标的最终低模表达、拓扑整理、比例修正、材质优化、宗教文化表达把关 | 可控性最高，便于控制风格、面数、原点、比例和导出质量 | 耗时较长，需要建模经验和审美判断 | 必须保留；所有 AI / MCP 产物最终都应进入 Blender 清理验收 |

结论建议：

- Codex + Blender MCP 适合低模符号化、场景批处理、材质和导出自动化。
- AI 3D 适合快速获得第一版复杂形体，但不能直接作为最终资产。
- 手工 Blender 清理仍然必需，是模型进入前端前的质量门槛。

## 3. Blender MCP 路线说明

Blender MCP 可以让 AI 通过工具控制本地 Blender，例如执行 Blender Python、创建几何体、调整材质、整理对象和导出文件。

适合：

- 创建低模场景。
- 创建规则几何体。
- 生成符号化建筑块、地台、莲座、塔、门楼等。
- 调整材质颜色、粗糙度和基础风格。
- 批量缩放、居中、设置原点。
- 清理对象命名和层级。
- 批量导出 GLB。

不适合：

- 自动生成高质量佛像细节。
- 完全替代人工审美。
- 直接做写实复杂建筑。
- 直接决定宗教文化形象的最终表达。

安全注意：

- 只能在本地受控 Blender 环境使用。
- 因为可能执行 Blender Python，应谨慎授权。
- 每次执行前保存当前 `.blend` 文件。
- 不要让 Blender MCP 读取或修改项目敏感文件。
- 不要让它接触 `.env`、API Key、token、Fay / gorse / 后端配置。
- 生成文件应先放在临时工作目录，验收后再移动到 `public/models/lingshan/`。

## 4. AI 3D 生成 / 重建路线说明

AI 3D 生成 / 重建工具通常可以基于单图、多图或视频生成 3D mesh。它适合快速获得第一版复杂形体，用于探索外轮廓、体块关系和材质参考。

适合：

- 快速生成灵山大佛的整体剪影参考。
- 快速生成梵宫、塔、坛城等复杂轮廓参考。
- 基于照片得到可观察的初始 mesh。
- 作为 Blender 手工低模重建的视觉参考。

风险：

- 结构不准。
- 贴图脏。
- 面数高。
- 原点、比例、法线混乱。
- 拓扑不适合实时渲染。
- 宗教建筑 / 佛像可能失真。
- 生成结果可能带有不合适的装饰和风格偏差。

生成后必须进入 Blender 清理：

- 减面。
- 修原点。
- 修比例。
- 修朝向。
- 修法线。
- 简化材质。
- 删除无关对象。
- 验收宗教文化表达是否庄重克制。

## 5. 推荐首个模型：灵山大佛

建议先做灵山大佛，原因：

- 地标性最强。
- 替换 placeholder 后视觉提升最大。
- 适合作为 GLB 加载、比例、原点、朝向、fallback 和移动端性能的首个验证对象。
- 可以先做低模庄重剪影，不必直接挑战写实佛像细节。

第一版目标：

- 佛像主体剪影。
- 莲座。
- 台阶 / 平台。
- 青铜或暖金色材质。
- 控制体积。
- 可在 `/three-preview` 加载。
- 可在 `/scenic-3d-map` 中稳定显示。

不要求：

- 高精度五官。
- 写实雕塑纹理。
- 完整周边建筑。
- 高面数重建。
- 复杂动画。
- 精确 1:1 尺寸。

## 6. 推荐制作流程

### 阶段 1：收集参考图

建议收集：

- 正面图。
- 侧面图。
- 远景图。
- 平台 / 莲座图。
- 颜色材质参考。

参考图只用于建模观察和形体把握，不应直接作为未经授权的贴图提交。

### 阶段 2：用 AI 3D 或 Blender MCP 出粗模

如果使用 AI 3D：

- 生成初始 mesh。
- 只把它视为粗模或形体参考。
- 不直接放进前端。

如果使用 Blender MCP：

- 用规则几何体组合佛像剪影。
- 生成莲座、底座、台阶和简化主体。
- 统一基础材质。

### 阶段 3：Blender 清理

必须执行：

- 减面。
- 修原点。
- 修比例。
- 修朝向。
- 材质统一。
- 删除无关对象。
- 检查法线和阴影。
- 检查模型底部是否贴地。
- 控制贴图和材质数量。

### 阶段 4：导出 GLB

流程：

1. 导出 GLB。
2. 放入 `public/models/lingshan/landmarks/`。
3. 配置 `lingshanAssetMap`。
4. 打开 `/three-preview` 验证。
5. 打开 `/scenic-3d-map` 验证。
6. 如果比例、朝向、位置不合适，优先调整 `transform`。
7. 如果 `transform` 无法解决，再回 Blender 修模型。

## 7. 首个模型验收标准

| 检查项 | 标准 |
| --- | --- |
| 文件大小 | 第一版建议小于 3MB，最好小于 1MB |
| 面数 | 移动端可实时渲染，不使用高面数重建直出模型 |
| 原点 | 底部中心，导入后不巨大偏移 |
| 比例 | 与现有 3D 地图节点和其它 placeholder 协调 |
| 朝向 | 正面朝向符合场景约定 |
| 材质 | 材质数量少，颜色庄重，避免复杂 shader |
| `/three-preview` 加载 | 选择对应 `poiId` 后模型正常显示 |
| `/scenic-3d-map` 加载 | 模型在地图中位置、比例和标签关系可接受 |
| fallback 正常 | 错误路径或加载失败时回退 placeholder，不白屏 |
| 移动端性能 | 手机端加载和旋转缩放基本流畅 |

## 8. 推荐优先级

1. 灵山大佛
2. 梵宫
3. 九龙灌浴
4. 五印坛城
5. 南门 / 大照壁 / 广场地台
6. 祥符禅寺 / 曼飞龙塔等 `simple_3d`

前 4 个是核心地标，适合优先制作 GLB。南门、大照壁、广场地台可以先用规则低模表达。祥符禅寺、曼飞龙塔等可在核心 4 个稳定后再做。

## 9. 不建议现在做的事

- 不要完整重建整个景区。
- 不要先做所有 19 个 POI 的复杂模型。
- 不要提交超大 GLB。
- 不要直接把 AI 生成高面数模型放进前端。
- 不要做娱乐化或夸张宗教形象。
- 不要让模型影响 `/map` 真实导航。
- 不要为了模型修改真实 POI 坐标或 routeGeometry。

## 10. 下一步建议

建议下一步：

1. 先做灵山大佛低模 GLB。
2. 接入 `/three-preview`。
3. 调整 `transform`。
4. 再接入 `/scenic-3d-map`。
5. 通过后再做梵宫、九龙灌浴、五印坛城。

推荐阶段：

- 阶段五十三：制作并接入第一个轻量灵山大佛 GLB。
- 阶段五十四：修正灵山大佛模型 `transform` 与视觉比例。
- 阶段五十五：核心 4 个地标模型批量接入。
- 阶段五十六：模型压缩、移动端性能与 Android 复用规范。
